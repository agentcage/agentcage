# Quickstart Tutorial

This hands-on tutorial walks you through your first five minutes with agentcage:
1. Launching a throwaway coding agent in a single command (`agentcage run`).
2. Observing how the egress sandbox blocks data exfiltration and credential leaks.
3. Building a persistent cage from a declarative configuration (`agentcage init` + `cage create`).
4. Using the in-egress Policy API to dynamically request access to new domains.
5. Inspecting structured audit logs and exporting traffic to Chrome DevTools.

---

## 1. Run an Ephemeral Agent Session (30 Seconds)

The fastest way to use agentcage is `agentcage run`. It automatically builds a hardened container, binds your current repository to `/workspace`, and launches the agent in an interactive terminal.

Navigate to an existing project:

```bash
cd ~/code/my-project
```

Launch Anthropic Claude Code inside a sandbox. Pass `-s KEY` to prompt for your secret without echoing it to your shell history:

```bash
agentcage run claude-code -s ANTHROPIC_API_KEY
```

> **Tip**: You can also provide the value directly via `-s KEY=VALUE` or configure automated retrieval from environment variables.

### What Just Happened?

Behind the scenes, `agentcage run`:
1. Generated a private bridge network (`Internal=true`) with no direct default gateway.
2. Built an unprivileged agent container running as UID 1000 with **all Linux capabilities dropped** and `no_new_privileges: true`.
3. Applied tmpfs overlays over `/workspace/.git/hooks/` and `/workspace/.claude/` to prevent host pivoting.
4. Minted a cryptographically random 128-bit decoy placeholder:
   ```text
   agentcage:secret:ANTHROPIC_API_KEY:a1b2c3d4e5f60718293a4b5c6d7e8f90
   ```
5. Set `ANTHROPIC_API_KEY` in the container to this placeholder value.
6. Handed the container a trusted per-cage CA public certificate (`/certs/ca-cert.pem`).
7. Forwarded outbound requests through the egress gateway, where placeholders are swapped for your real API key only on the wire.

When you exit Claude Code (e.g. typing `/exit`), the ephemeral cage and network namespaces are automatically destroyed, while your workspace edits remain intact on your host.

## 2. Testing the Sandbox Boundaries

Let's test the sandbox boundaries directly by opening an interactive shell inside a throwaway sandbox:

```bash
agentcage run debian
```

Inside the cage container shell, test the defenses:

### A. Inspect Environment Variables
Check what credentials the agent sees:

```bash
echo "$ANTHROPIC_API_KEY"
# Displays the decoy placeholder, NOT your real key:
# agentcage:secret:ANTHROPIC_API_KEY:4f2a...
```

If an attacker prompt-injects the agent and tricks it into uploading its environment, they only obtain a useless placeholder string.

### B. Attempt Unauthorized Outbound Egress
Try making an outbound request to an unauthorized server:

```bash
curl -I https://example.com
```

Output:
```text
HTTP/1.1 403 Forbidden
content-type: text/html
x-agentcage-decision: blocked
x-agentcage-reason: domain 'example.com' not in allowlist
```

The request does not hang or time out. It fails immediately with a clear `403 Forbidden` response generated by the proxy, saving time and token budgets.

### C. Attempt Raw IP & Non-HTTP Connections
Try pinging a public IP address or establishing a raw socket connection:

```bash
ping -c 1 8.8.8.8
# 100% packet loss — raw ICMP is dropped by iptables

nc -zv 1.1.1.1 53
# Connection dropped — non-HTTP egress is blocked
```

Exit the test shell:

```bash
exit
```

## 3. Creating a Persistent Cage

For agents that run long-term tasks, background services, or require customized domain allowlists, create a persistent cage.

### Step 1: Initialize Configuration

Generate a clean `cage.yaml` template using the `init` command:

```bash
agentcage init my-agent --scaffold claude-code
```

This writes a commented `cage.yaml` in your current directory. Inspect the configuration:

```yaml
name: my-agent
isolation: container         # Auto-detected (container, apple-container, or vm)
lifecycle: service           # Starts on boot, restarts on failure

container:
  image: "node:22-slim"
  command: ["bash"]
  user: 1000:1000
  read_only: true
  drop_capabilities: [ALL]
  volumes:
    - ".:/workspace:rw"

domains:
  mode: allowlist
  allow:
    - api.anthropic.com
    - github.com
    - registry.npmjs.org
```

### Step 2: Store Encrypted Secrets on the Host

Store your credentials encrypted in host storage (`systemd-creds` on Linux, Keychain on macOS):

```bash
agentcage secret set my-agent ANTHROPIC_API_KEY
```

Enter your secret value at the secure prompt.

### Step 3: Build and Start the Cage

Build the container images, generate user quadlets, and launch the cage services:

```bash
agentcage cage create -c cage.yaml
```

Check the status of your new cage:

```bash
agentcage ps
# Or: agentcage status my-agent
```

### Step 4: Execute Commands Inside the Cage

Attach an interactive shell or execute commands inside your running cage:

```bash
# Execute a single command:
agentcage exec my-agent -- node -v

# Open an interactive bash shell:
agentcage shell my-agent
```

## 4. Using the Policy API (Dynamic Egress)

What happens when an agent needs to access a new package repository or documentation site that wasn't in the initial allowlist?

Instead of failing or requiring the operator to manually edit configuration files, agentcage provides the internal **Policy API** served at `https://agentcage.local`.

From inside your cage (e.g. via `agentcage shell my-agent`):

### A. Introspect Reachable Domains
An agent can inspect its own effective allowlist:

```bash
curl -s https://agentcage.local/v1/allowlist | jq .
```

Response:
```json
{
  "mode": "allowlist",
  "static": [
    "api.anthropic.com",
    "github.com",
    "registry.npmjs.org"
  ],
  "grants": []
}
```

### B. Request Dynamic Egress Access
The agent requests access by providing the requested domain and a technical justification:

```bash
curl -s -X POST https://agentcage.local/v1/allowlist/requests \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "crates.io",
    "reason": "Need to download serde crate dependencies for the project build."
  }' | jq .
```

### C. Autonomous Decider Evaluation
If the operator enabled the **Decider Agent** in `cage.yaml`:
1. The request is evaluated by an in-egress LLM acting as a cybersecurity reviewer.
2. If approved, the domain is promoted into the active runtime filter within approximately 1 second.
3. `crates.io` is now immediately reachable.

On your host machine, the operator can inspect or revoke dynamic grants at any time:

```bash
# View active dynamic grants:
agentcage cage grants my-agent list

# Promote a grant permanently into cage.yaml:
agentcage cage grants my-agent promote crates.io

# Revoke a grant immediately:
agentcage cage grants my-agent revoke crates.io
```

## 5. Monitoring & Forensics

agentcage gives operators complete observability into every network flow leaving the sandbox.

### A. Stream Real-Time Logs

```bash
# Stream agent container stdout/stderr:
agentcage logs my-agent -f

# Stream egress proxy logs:
agentcage logs my-agent -s egress -f
```

### B. Query Structured Audit Decisions

Every proxy decision is recorded in `audit.jsonl`:

```bash
# View summary statistics of allowed vs blocked requests:
agentcage cage audit my-agent --summary

# Stream only blocked requests in real time:
agentcage cage audit my-agent -f --decision blocked
```

### C. Export Full-Body HTTP Captures to HAR

Export captured traffic to standard HTTP Archive (HAR 1.2) JSON, loadable into Chrome DevTools (Network > Import HAR):

```bash
# Export the "inbound" perspective (safe to share; contains only placeholders):
agentcage cage har my-agent --view inbound -o safe-traffic.har

# Export the "outbound" perspective (wire view with real secrets; handle securely):
agentcage cage har my-agent --view outbound -o wire-traffic.har
```

---

## 6. Tear Down & Cleanup

When you are finished with a persistent cage:

```bash
# Stop and delete the cage, containers, and scoped secrets:
agentcage rm my-agent

# Prune any exited ephemeral containers:
agentcage cage prune -y
```
